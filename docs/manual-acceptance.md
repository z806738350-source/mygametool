**2026-11-03 接续门槛：**执行存储协议 2 的源码与模拟测试不等于已升级真实 VM。旧组件、未经审计的身份范围会拒绝执行，不应通过手填批准账本绕过。需另行维护并完成真实第九项目、取消恢复和删除验收；当前应用与账号未更改。具体约束见 [执行存储生命周期](isolated-storage-lifecycle.md)。

本项目使用改后的本地源码，基线 `42d7e21e396d9adef7a79081416d9cf3b1a97663`。没有制作安装包、提交或发布。自动化与模拟验证的最终结果见 [本轮检查记录](pre-acceptance-check.md)；Kunpo 型号、默认值及未接入能力见 [模型适配说明](kunpo-local.md)。

## 启动与停止

1. 首次可以保持项目根 `.env` 为空，双击 **启动 OhMyGame.command**。不需要原作者账号，空 Key 可使用本地编辑流程。
2. 需要模型时，先退出应用，用文本编辑器在项目根 `.env` 的 `KUNPO_API_KEY=` 后填写你自己的字面量 Key。不要加引号、空格、`export` 或变量插值。不要把文件发给别人或提交到 Git。
3. 再双击启动。它使用本项目 `.runtime/toolchain` 中已核验的 Node/Electron，不使用全局 Node，不自动下载安装依赖；源码改变时只执行已准备的本地编译。准备期间请保留启动窗口。
4. 重复双击会唤起现有实例，不重复创建服务。**点主窗口红叉或按 ⌘Q 都会先保存，再完整退出**，正常退出后无需再点停止脚本。**停止 OhMyGame.command** 保留为后台或异常时的备用入口。保存失败或超时会保留窗口并显示现有提示，处理后可重试。正常退出会先结束事件流、任务和预览，再回收本次 VM；异常退出的保护等待有上限，最多约三分钟，不要反复强退或直接删除回执。

**启动本身不提交模型任务。** 你点击发送、生成或手动重试后，真实上游请求可能计费；结果未知时不要连续重发。先验一个小任务，再决定是否测试昂贵的媒体功能。

启动器不使用 `source`/`eval`，不读取其他项目的环境文件。它只把本项目 `.env` 路径交给 daemon；Vite、界面、VM 与任务 Shell 不继承 Key。daemon 将当前值放入独立的 0600 私有凭据快照，进程内重启复用这份快照；完整退出、修改 `.env` 后再次启动才重新导入。空模板会清空这一启动快照，不复用旧账号密钥。快照位于 `.runtime/local-execution/manual-data/local-env-api-keys.json`，同样不要分享；当前设计不是系统钥匙串加密。

`.env` 只接受注释、空行及一条 `KUNPO_API_KEY=`。权限由启动器收紧至当前用户读写；非法格式仅报告错误，不展示内容。若提示运行时校验失败、依赖缺失或文件权限异常，请停止并保留报错，不修改校验值、不手动下载替代程序。

## 当前功能边界

| 功能 | 本地版范围 |
| --- | --- |
| 项目、代码、画布、素材、故事 | 本地保存与导入导出；秘密文件、链接越界及已登记 Key 内容拒绝交付 |
| Agent | GPT-5.6 Sol、Claude Opus 5.5、Claude Fable 5.2、GPT-6.2 Astra 均支持图片输入与项目工具调用 |
| 文件工具 | 受保护的 read/write/edit/搜索；不允许读取凭据与私有目录 |
| Shell、依赖、动态构建与预览 | 仅专用 VM 工作副本；离线任务、硬配额、回传检查及并发冲突拒绝；不等于开放宿主 Shell |
| Web 自动试玩 | 四个 Kunpo 主 Agent 均可在 Electron 的可试玩项目中调用 `game_use` 点击、按键、触摸和截图 |
| 原生引擎、外部 CLI/MCP/插件 | 框架保留，通用安装/执行仍关闭；不宣称已恢复 |
| 登录、作者 Cloud/Community、发布、遥测、自动更新 | 本地版退役，不能通过环境变量重新开启 |
| 音乐、严格配音、部分视频操作 | 完整 BGM 无已确认默认；SeedAudio 严格朗读/音色需人工验证，无字幕承诺；未接入编辑/延长不提供入口 |

Code 面板目前是代码查看器；手工改代码可使用现有“外部编辑”入口，或由 Agent 受控文件工具修改。画布、文档和表格等使用其原有编辑器。桌面窗口的最小尺寸沿用 960×640。

安全检查也有大小边界：原始项目文件/静态预览每文件 64MiB；Library 每素材 200MiB；ZIP 单条 128MiB、未压缩合计 512MiB、最多 10,000 条。超限明确拒绝；发送快照会占用对应大小的内存。已知值检查仅覆盖当前 daemon 登记的值，不是任意秘密识别器。

独立 Web 构建/测试 ZIP 本轮通过受控后端开发入口验证；没有新增 Web 发行打包按钮。人工可以先验现有动态预览和 game_use。

动态执行需要现有专用 Lima/Ubuntu VM，首次任务或明确确认删除项目时按需启动，不挂载宿主 HOME、不传 Key。每项目可写工作卷 256MiB，共享 8 个驻留名额；休眠卷与总容量限制见[执行存储生命周期](isolated-storage-lifecycle.md)。支持根目录或所选子目录的单个 npm 包；不是完整 monorepo 解析器。仅支持受审公共 npm 锁文件子集，拒绝 Git/任意 URL/私有凭据与安装生命周期脚本。具体包数、传输及超时上限以界面错误为准。已有运行中的 VM 不属于此次启动时，不会擅自停止它。

## 建议人工顺序

以下以**简体中文界面**为准，英文界面可按括号内名称找入口。先做第 1、2 项，再只做第 3 项的第一条短消息；成功后自行决定要测哪些媒体，**不要求一次跑完全部收费项目**。短提示词、短时长和较小尺寸只是控制测试量，不保证某个型号收费最低，提交前请在 Kunpo 当前账号查看可用型号、余额和价格。

| 顺序 | 测什么 | 首轮建议 |
| --- | --- | --- |
| 1、2 | 本地保存、窗口与退出 | 无 Key 即可 |
| 3 | Agent 回答、文件工具 | 先一条短回答，再一次文件任务 |
| 4 | 图片 | 先一张 Sunburst；编辑、透明、mask 是额外选测 |
| 5 | 视频 | 先一个 4 秒任务；不要同时比较多个型号 |
| 6 | 音效、配音、音乐 | 分开记录；音乐和严格朗读仍是待验证能力 |
| 7 | 3D | 先一个简单物件；后处理各自按需付费 |
| 8 | 执行与试玩 | 先人工 Play，再测 Agent 的自动 game_use |
| 9 | 取消、重开、导入导出 | 优先利用前面已有任务与产物，不专门制造昂贵失败 |

### 先认清几个位置

- **界面语言**：首页左下角「设置 / Settings」→「外观 / Appearance」→「工作区 / Workspace」→「语言 / Language」→「简体中文」。会自动刷新界面，无需退出重启。模型设置里的 Language 分类是语言模型类别，不是这个开关。
- **素材画布**：左侧「素材画布 / Asset Canvas」→「新建素材画布」。创建时只填一个测试名称，工作目录保持默认，不选业务文件夹。画布标题 `Untitled` 是默认画板名，并不表示项目未保存。
- **新增节点**：右侧点阵画布**底部中央「＋」**→「文本 / 图像 / 视频 / 语音 / 音效 / 音乐 / 3D 模型 / 3D 动画」。新建后单击卡片，选中时会展开其下方参数和输入框。手工文字写在文本卡片的「生成或手写的文本」区域；不要为了保存手写内容点击生成。
- **定位节点**：画布小地图标出节点与当前视口，点击远处节点或拖动小地图可以移动视图，保持当前缩放。点小地图右上角箭头可收起为地图图标按钮，再点该按钮展开；会在本机记住收起状态，按钮可用 Tab 聚焦后按 Enter 或空格操作。宽画布时在右下，窄画布时移到右上，避开底部工具。也可用底部手形工具平移、「适应视图」找回节点；卡片靠近窗口下沿时，先向上平移，为下方参数留出空间。
- **画布缩放快捷键**：先单击画布空白，或通过 Tab 聚焦画布，再按 `+` / `=` 放大、`-` 缩小、`0` 恢复 100%（保持当前中心）、`F` 适应全部节点；小键盘加减号与数字 0 也可使用。素材、游戏设计与互动故事画布采用同一组按键；输入框、聊天、代码、菜单、弹窗、媒体查看器与试玩区域不会触发。长按不会连续缩放，现有滚轮与触控板操作保持原样。悬停原有缩放按钮可看按键提示。
- **项目与节点的模型**：画布或设计区右上角滑杆图标，悬停为「默认模型」，按角色设置项目默认；每个节点下方的模型按钮可单独选择。已有节点/会话可能保留显式选择，测试前以**当前节点或聊天框实际显示的型号**为准。新手先从空画布加节点，避免首页型号快捷卡片选择了与首选不同的模型。
- **两个输入位置**：Agent 聊天框用于发工作指令；图像、视频等卡片下方的输入框用于该节点的生成提示词。媒体节点末端的 **↑** 悬停会显示「生成图像 / 生成视频 / 生成音频 / 生成 3D 模型」等；生成中变为 **■** 取消按钮。不要把它与聊天框的发送按钮混淆。
- **配置是否被识别**：按上面的启动步骤自行填写 Key、完整退出再启动后，可到「设置」→「服务商与模型」→「KunpoAPI」查看是否为已配置/掩码状态，再返回应用。不需要向聊天框粘贴 Key，也不要在测试截图里展开密钥编辑框。列表里的「未实测」表示尚未验证真实服务；「待接入」条目禁用，不属于本轮可成功调用的型号。

聊天区与工作区的左右位置可以在外观设置中对调；如果与你看到的位置不同，以「代码」「预览」等名称和按钮悬停提示寻找，不必先改回默认布局。

### 素材库批量操作，无需模型调用

左侧「素材库」中的每张卡片左上角都有勾选框，点击卡片本身仍打开预览。「全选当前结果」只选择当前媒体分类、搜索和来源筛选下显示的素材；可再次点「取消全选」或「清空选择」。切换筛选后，隐藏的素材退出选择，不会被后续批量操作处理。

主素材库默认显示已保存的参考素材，便于检查、下载和清理历史上传。筛选中的「包含参考图」可关闭；重置筛选会恢复显示。参考选择器每次打开都会刷新可用列表，已删除项不会因页面缓存一直留在候选中；打开着的旧选择器可关掉重开核对。不自动删除任何历史文件。

分类栏中的「未引用的」会检查所有已保存项目的真实引用，仅显示确认未被使用的素材，仍可叠加搜索、来源筛选并全选当前结果。项目不可读、工作目录丢失或检查失败时，对应素材按未知处理，不算未引用；可用刷新按钮重查。切换分类、刷新素材或回到窗口后会重新检查，旧检查结果不沿用。较窄窗口中分类按钮保持相同高度和间隔，搜索换到下一行，分类继续换行。

清理前先保存所有打开的画布。发现同源浏览器恢复存储中任意项目/版本的画布、文档或表格草稿，或恢复记录损坏/读取失败时，暂停「未引用的」结果及所有素材库删除入口；保存或处理恢复草稿后刷新再试，不自动删除恢复记录。删除确认后、批量删除的每个文件发送请求前仍会重查草稿，服务端也重新检查已保存引用。其他窗口尚未写入恢复存储的内存编辑、写入配额失败和不同浏览器来源/配置的草稿无法由该分类发现；它是已保存引用的检查快照，不代表所有打开窗口的实时内存状态。

选中素材后可「下载所选」，每个文件按原名称分别下载，浏览器可能要求允许多个文件下载；筛选出尚未保存或仅作参考的素材时，还可「将所选保存到素材库」。单项失败会注明文件名，其余项继续处理。

「删除所选」先检查项目引用，再列出将删除的文件并要求确认。正在被项目使用的素材会列出相关项目并保留，画布引用也保留；没有可删除项时不会提供确认删除按钮。确认前可取消或按 Esc，确认后删除无法撤销。删除失败的素材保持勾选，成功项退出选择。只用可丢弃的测试副本验收删除，不需要删除真实生成结果。

### 存储与清理，无需模型调用

「设置 → 存储与清理」适用于支持该功能的桌面源码版；浏览器模式明确显示不可操作。刷新只读取占用，不删除文件。分类显示磁盘已分配占用与逻辑大小，采用 KiB/MiB/GiB，并保留精确字节数。无法完整测量的路径显示部分统计和未知状态，不以 0 当作完整零占用。

默认不勾选候选。可逐项、逐类或全选经过核验的可清理项；项目、素材、恢复草稿、必要备份、运行依赖、活动文件与未知路径不可选。运行中的浏览器缓存保持禁选，页面不会自行退出或重启应用。先保存所有打开的画布；任何项目/版本的本地画布、文档或表格恢复草稿未保存，或恢复存储不可读时，都阻止生成删除清单和执行。

「查看删除清单」重新核验所选项，显示目录基准、每个实际文件路径、影响、体积和有效期，不截断精确文件清单。用户须勾选理解无法恢复，再点击最终「永久删除」；取消或 Esc 不执行。永久删除直接移除文件，不移入废纸篓或隔离目录。确认前再次检查草稿，桌面服务也复核计划、文件指纹及活动状态；变化或过期要求重新查看清单。清理结果逐项显示已删除、保留或失败，按文件原已分配占用报告，系统可用空间变化可能受到文件系统快照影响。

若执行时 IPC 中断，先查询原计划结果，不自动重发删除请求；结果未确定前不能计划新删除。明确的执行前拒绝可刷新后重新查看清单。跨设置页仍可查询本次进程中的待确认结果；不将进程崩溃或断电解释为可回滚事务。草稿检查仅覆盖同源可读恢复存储，不能代替保存其他窗口尚未落盘的编辑。

功能验证仅在独立测试目录或模拟桌面桥中进行。真实安装的扫描与清单准备不等于授权删除；需对最终精确清单单独确认后才可执行。

### 第 1 项：不填 Key，确认文字保存

1. 双击项目根的「启动 OhMyGame.command」。如出现欢迎向导，点「下一步 / Next」，再选「跳过并开始 / Skip and start」；已有设置的用户可能直接进入首页。
2. 左侧「素材画布」→「新建素材画布」，名称填 `人工验收-素材`，直接创建。
3. 点画布底部「＋」→「文本」，在新卡片中手写 `第一次保存测试`。若输入区只读，先单击选中这张卡片。
4. 等状态显示「已保存 / Saved」，通过项目左上角返回按钮回到列表或首页，再打开同一项目，确认文字还在。
5. 按 `⌘Q` 退出，重新双击启动，再打开该项目检查一次。

**通过标准**：无需原作者账号，文字没有丢失；没配置模型时生成/发送会禁用或有明确提示，本地编辑仍可用。重开后节点可能不再有选中高亮，这是临时编辑状态，不作为文字丢失；项目默认或已显式保存的模型参数另行检查。

### 第 2 项：不填 Key，确认窗口与退出

1. 在主窗口已打开时再双击「启动 OhMyGame.command」，预期复用现有实例，不出现第二套工作窗口/服务。首次准备期间不要连续双击催促。
2. 首页左下角「设置」→「外观」，更改一个主题选项，再点「返回应用」。打开一次新建项目弹层并用其关闭按钮或 `Esc` 返回，不必创建另一个项目。
3. 调整窗口宽度，检查设置、返回按钮、模型弹层是否能操作。Mac 可使用菜单「Window」→「Move & Resize」→「Left」缩窄；桌面最小尺寸为 960×640，不要求缩成手机宽度。完成后恢复适合自己的窗口大小。
4. 点**主窗口红叉**退出，重新启动，再按 `⌘Q` 退出。两种方式都应先保存再结束本次后台服务；正常情况下不用再双击停止脚本。不要靠强制退出来判定正常关闭通过。
5. Play 试玩子窗关闭、自己启动的 VM 回收可结合第 8 项测试。仅打开画布不会启动 VM；没有启动过 VM 时，此子项记「未涉及」，不能据此说已测过 VM 回收。Agent 试玩窗口需要活动的 game_use 会话，人工 Play 通过不能替代它。

**失败时**：若保存错误留下窗口，先记录提示，处理后重试退出。等待关闭期间不要反复点关闭、删锁文件或停止其他程序；超过启动说明的保护等待仍不退出时，使用「停止 OhMyGame.command」作为备用入口并报告。

### 第 3 项：主 Agent，先回答再读写文件

参数按钮会根据节点宽度换行，模型、比例、分辨率和取值应能辨认；「画质」「背景」在按钮中有简短前缀。蒙版没有参考图时禁用是预期行为。滚轮策略保持原样：列表、设置和输入区正常滚动，无限画布平移；画布缩放可使用上面的独立键盘快捷键。

### 第 5 项：视频，先一个短任务

**入口**：素材画布底部「＋」→「视频」。先不要接参考图，用纯文字减少变量。

1. 「视频模型」选首选 `doubao-seedance-2-5-260628`（显示名可能是 Doubao Seedance 2.5），宽高比 `16:9`，时长 `4 秒`，分辨率选择列表中较低的可用档位。别直接选 4K 或最长时长来测连通性。
2. 输入：`固定镜头，一颗蓝色小球在浅灰背景上缓慢滚动，无人物、无文字。`
3. 点一次卡片末端「生成视频」，记录项目名、画板名、型号、时间和规格。等待时不要换型号、复制节点继续生成或反复点击；视频提交的 HTTP 等待已与应用最长 15 分钟的总期限协调，取消可停止本地等待。超时不代表上游没接单，也不会自动重发生成。
4. 成功后在卡片内点播放，检查能播放、内容大致符合、实际时长和画幅合理；右键节点→「下载」。已完成后退出再打开，检查产物仍可播放。
5. 只有决定额外测试参考模式时，再新建视频节点：选支持的「首帧 / 尾帧」或「图片参考」，通过参考区「＋」选测试图片，再填运动描述。参考图可能改变可选宽高比，按界面提示选择，不强行保留不兼容值。

**参考图副本**：来源可验证且内容未改动的 Kunpo 生成图优先使用原 CDN 链接。本地 PNG/JPEG/WebP 会按完整请求的本地 768KiB 目标处理：先保留较高画质，必要时生成 JPEG 或缩小副本，卡片沿用现有区域提示，原图不变。透明、动画等不会被强行铺背景或取单帧。若提示超出本地目标、尚未提交，本次没有发送生成请求；请减少参考图或换较小的不透明图，再由你决定生成。该目标不是 Kunpo 官方限额，也不保证上游接受；不要把已有任务的「续查」换成新生成来重试。

**比例切换**：新建视频节点默认「图片参考」、无图 `16:9`，可直接做纯文字测试；该模式加图后可选 `adaptive` 或固定比例。选择「首帧 / 尾帧」就只显示 `adaptive`，空图时也不例外：提示「添加首帧后生成。」，生成按钮禁用。通过「首帧」加图后才能生成，尾帧按需再加；删掉最后一张图仍保持 `adaptive` 并禁用生成。要无图生成，请切回「图片参考」，比例会自动调整为固定值。你主动切模型、切参考模式、添加或删除参考图时，草稿保留兼容参数、自动调整不兼容规格，不显示普通重置提示。超过首尾帧两张上限时该模式不可选，不会替你删图。旧节点单纯打开不改写保存数据；旧空图首尾帧节点界面显示 `adaptive` 并等待首帧。「续查已有视频」仍可用，始终使用原任务参数，独立于当前草稿。

**恢复已有视频**：失败或取消后，若已保存有效任务，卡片参数区会显示带下载图标的「续查已有视频」。它使用原任务 ID 和原参数查询、下载，不提交新生成；即使记录在操作前丢失，也会拒绝操作，不会退回重新生成。续查中的 ■ 是「停止续查」，仅停止本地等待，不承诺上游取消或退款。没有保存任务时不显示此入口；保留节点和时间，请技术侧核对，不要盲点 ↑「生成视频」。应用完整退出后不会自动续查，重开项目再点上述按钮。视频临时地址可能过期，已成功的任务应及时取回；取回仍须通过公网地址、可信 CDN、重定向和文件大小检查。不要打开私有凭据文件寻找任务 ID。

**其他选测**：`tencent-vod-vs-2.5`、`minimax-video-h3` 各用新节点、各自检查可选规格，只有愿意承担额外任务费用时才生成。当前不提供模型视频编辑/延长、本地视频参考或完整音频参考入口。下载视频后的本地裁剪不是模型编辑/延长，不能混作通过。

**失败时**：截取节点错误和规格，隐去私人内容；新错误会附带可安全分享的 HTTP 状态 / 固定类别，历史诊断仅保存受限枚举，可区分连接、响应头、响应体或总期限超时，不展示上游原始正文、Key、图片或签名 URL。结果未知、网络中断、超时、任务状态无法识别时先停在原节点；没有已保存 ID 时不能直接续查，不要通过再生成来试探，应先核对后台原调用。取消只是停止本地等待，不承诺上游撤单或退款。

### 第 6 项：音效、配音、音乐分别验

音色、语音、音效和音乐都在素材画布底部「＋」中创建，选择卡片后在下方「音频模型」选型号。不要用一段能播放的音频来替代三类能力全部通过。

**6A 音效，建议先做这一项**：

1. 新建「音效」节点，选 `Seed Audio 1.0`（路由 `seed-audio-1.0`），时长选 `5 秒`。
2. 输入 `一个游戏宝箱开启的短音效，木盖轻响后有清脆铃声，不要人声，不要背景音乐，总长约五秒。`，点一次「生成音频」。
3. 返回后点卡片播放器的播放按钮，先用合适音量听一次；检查没有人声、能听到宝箱/铃声。下载并重新播放，确认是有效音频，不是只看到了下载按钮。

**6B 音色与角色配音，按需要选一条路线，真实生成均可能收费**：

1. **先试无参考配音，调用最少**：底部「＋」→「语音」，选中卡片，模型选 `Seed Audio 1.0`，语速「正常」。在台词框输入 `你好，欢迎来到测试小镇。请点击蓝色按钮。`。不添加参考也应能生成；只在愿意承担费用时点一次生成。没有参考时由模型决定声线，不保证固定男女声或每次同一人。
2. **按描述设计音色，可单独选测**：底部「＋」→「音色」。上框填 `温暖、慵懒的成年女声，清晰自然，不带背景音乐。`，下框是已填好的短试听样文，可修改。确认模型和费用后点一次生成。返回后播放、暂停，比较声线和描述；描述不应被念出来，样文不应乱加词。能播放不等于描述遵循或稳定性通过。
3. **选用并连接，无需模型调用**：从音色节点右侧连接点拖线到语音（卡片标题为「音频」）节点左侧：尚未选用时，这次拖线会校验并选用当前已生成样音；也可以先点「选用样音」再连接。如果已经选用了某个版本，新连线优先使用该版本。语音节点应出现参考音频缩略图；可播放、暂停、移除。选用和连接本身不生成配音。随后只有主动点语音节点生成，才会发送样音和台词并产生下一次模型费用。
4. **也可以直接用自己的参考**：在语音节点台词上方方形「＋」中选择或上传有权使用的 **MP3/WAV**。建议先选 3～10 秒、单人清晰说话的短音频，必须不超过 30 秒和 10 MB。工具按内容识别 MP3/WAV；如果这两种文件的后缀写反，只纠正导入副本的名称和类型，不改原文件或音频内容。当前不接入 M4A，不能改扩展名冒充 WAV。不要上传私人谈话或含敏感信息的录音。选文件、试听和移除不产生模型请求；更换参考会替换当前绑定，不把两个声音混在一起。
5. **确认版本不会偷偷变**：先保留已绑定的语音节点。若你本来就准备承担一次新的样音生成，可改音色描述再生成：原语音参考仍须保持不变。即使在音色节点选用了新样音，语音节点也应保持旧版本，直到你明确点「更新音色」。更新引用不收费，也不自动生成配音。不必为了这项额外连续生成昂贵任务，可先记录「待选测」。
6. **移除与失效**：缩略图的 × 表示明确移除参考，回到无参考配音；断开连线或删除音色节点则保留已经选定的音频资产。文件缺失、内容变动或超出参考限制必须阻止带该参考提交，不能自动换成无参考。旧项目只有已退役音色 ID 时，选择新音频或明确点「不使用参考」后再继续。
7. **检查输出与保存**：逐字听查漏字、多字、乱加台词、参考内容被重复朗读及音色相似度。关闭并重开**已保存**的画布，检查描述、样文、选定样音、连线和输出。音色重新生成只增加候选；已选版本应仍在。导出项目可能包含原参考和选用样音，分享前确认授权和隐私。

音色设计是「生成声音候选音频」，不是创建永久 Speaker ID。严格朗读、描述遵循和跨次音色一致性仍需真实试听；没有字幕、字级对齐、多角色对话保证。生成超过 30 秒的候选可以保留，但不能直接作为参考；不要自动重发或偷偷裁剪。multilingual 是单独的多语言候选，不用一次把所有型号都测完。

**6C 音乐，完全可暂跳**：新建「音乐」节点，手动选 `Seed Audio 1.0` 短环境音乐候选（项目没有已确认的音乐默认），选 `5 秒`，输入 `五秒钟舒缓的游戏环境音乐，轻柔木琴，无人声。`。若愿意承担额外费用才生成；听到和谐声音不等于完整 BGM、无缝循环或歌词能力通过。时长是请求/提示，不保证采样精确。当前没有循环、歌词能力就不应出现可用控件，不要用提示词伪装成已支持。

**失败时**：音频是非流式二进制，生成过程中不会实时播放，等待响应头（含上传）最多 300 秒，接收音频最多 180 秒，总上限 480 秒；连接失败可能更早返回。网络中断或结果未知后没有可查询的通用音频任务 ID，不自动重发；保留错误并暂停。若再点生成，应先明确提示这是新的收费请求，取消确认不得发送请求；它不是找回旧结果。本地格式/时长校验失败应先换有效参考，不应产生生成请求；上游失败则记录脱敏错误和时间，不把它误判为工具全坏。

### 第 7 项：3D，生成与后处理分开

**先做一次简单生成**：

1. 素材画布底部「＋」→「3D 模型」，单击卡片，在「3D 操作」改选「文生 3D」。默认「图生 3D」需要参考图，空着参考直接输入文字不会满足它的条件。
2. 「3D 模型」选 `v3.1-20260211`，面数选界面允许的较低档位。首轮可关闭「贴图」与 `PBR`，先验几何；不同参数如何计费以账号为准。
3. 输入 `一个简单的低多边形木箱，方正造型，封闭表面，单个物件，无人物。`，点一次「生成 3D 模型」。
4. 完成后点模型预览的查看图标放大检查，尝试旋转观察形体；右键节点→「下载」，确认有实际模型文件。模型能打开与几何质量好坏分开记录。

下面每项都是**额外工序，可能分别计费**。不要拿同一个节点切操作覆盖原来的验收上下文；新建节点再选源模型。

- **减面**：新建「3D 模型」→「3D 操作」选「重新拓扑」，在源模型参考区「＋」选择刚生成的 GLB，处理连接选当前 Kunpo/Tripo 连接，目标面数选比源模型低的可用档。该链使用减面版本 `v3.0`；「四边面」「智能 UV」按需选，不是另找两个模型。点生成后比较形体与面数；当前只接收 GLB 回收链，若上游返回其他格式应明确报错，不把改扩展名当成功。
- **重贴图**：新建「3D 模型」→「重新贴图」，添加源 GLB，贴图版本选 `v3.5-20260815`，质量先用标准，输入 `木箱使用浅蓝色哑光木材纹理。`，或选一张测试参考图；当前 Tripo 此工序在文字与参考图之间二选一，不同时填。只有需要贴图时才提交；原始生成的贴图已经满意，可以不跑。
- **绑骨与动画**：物件木箱不适合人形绑骨。只有准备了自己可使用的、姿态合适的人形 GLB 时，再建「3D 动画」节点→参考区「＋」选该模型→动画服务商选对应连接→「骨骼版本」`v3.0-20260909`、骨骼类型选人形→点「0 个动作」选择一个兼容动作→生成动画。这个按钮会走兼容检查、绑骨、retarget 等多步，**不是只买一个独立模型请求**。retarget 是操作，内置链使用 `tripo` 骨骼规范，不需要再选一个 retarget 模型。最多 5 个动作，首轮只选 1 个。

非人形需按类型使用 `v2.5-20260210` 和兼容动作；others/avian 等缺少已接入动作预设的类型当前被禁用，也没有单独绑骨入口，记未测即可。`v3.1-20260211`、`v3.0`、`v3.0-20260909` 是不同工序版本，不是每次都必须连跑的三选一或套餐。

**失败时**：没有源 GLB、没选动作、面数越界会阻止生成，先看卡片提示。模型不适合绑骨时不要反复付费尝试。上游没有取消接口，停止本地等待后任务可能继续收费。3D 暂无一键续查入口，保留节点、时间和错误，请技术侧协助；不要把第 5 项的视频按钮当作 3D 入口。底层重试只查询、下载已记录阶段；记录缺失、参数变化或后续工序还没提交时会停下，不会自动补交收费任务。「生成」会另开工作流，可能重付整套工序费用；当前不能单独补做尚未提交的后续工序。

### 第 8 项：执行与试玩，先人工再自动

**8A 人工 Play，无需模型**：如果项目列表仍保留 `CU正常启动Web-20261029`，可以使用这个专门测试项目；它有无外链的计数页面与无依赖 Node 脚本，不要换成业务项目。

1. 打开该项目，选右侧「预览」。工具栏扳手图标→「项目设置」，在「启动配置」确认目录 `.`、预览模式「package 脚本」、脚本 `dev`、包管理器自动或 npm；保留「自动预览」关闭，保存。
2. 当前预览已经运行时，改配置可能会重启这次预览；关闭自动预览控制的是以后自动启动，不等于立即停止已运行的预览。没有运行时，在预览区点「启动预览」。等待「安装/启动」变成页面；此测试没有外部依赖，不需要下载包或 Key。
3. 工具栏悬停显示「在窗口中试玩」的三角按钮打开 **Play 子窗**，点一次「点击计数」，确认 0→1；关闭这个子窗红叉，主窗口应继续工作。`Play` 是明确的启动请求，即使关闭了自动预览，点它也会启动所需预览/VM。
4. 主窗口红叉退出后，这次自己启动的 VM 应停止；若 VM 原先由其他会话运行，应用不会擅自关闭。用户可确认窗口消失、正常重开；daemon/VM 是否完全回收需技术侧看进程和所有权记录，单凭窗口消失不能证明。不要删除 `.runtime` 或回执来清理。

**若没有上述测试项目**：新建受管理的「网页游戏」项目，不选外部文件夹；在第 3 项已连通的 Agent 中发送以下请求，准备文件会产生 Agent 费用：

```text
In this new test project only, prepare a web game with no external dependencies. Create index.html with a blue click-counter button and separate Enter-key and touch counters, all initially 0. Do not use external resources or generate media. Create server.mjs using only Node's standard library to serve the page on the configured loopback HOST/PORT. In package.json, set dev to "node server.mjs" and build to "node build.mjs". Let build.mjs only copy the page to dist. Include a matching npm v3 package-lock.json with no dependencies. For now, only write and read back these files. Do not install software, run host commands, or read outside this project.
```

文件存在后，再按 8A 的项目设置启动动态预览。单个 npm 包支持根目录或所选子目录；外部工作目录不属于这个隔离执行后端，普通多包 monorepo、私有 registry、Git/任意 URL 依赖或需安装脚本的包不能照此宣称支持。

**8B 受控命令与构建，选测**：在有 `build` 脚本的自建测试项目，发 `Use isolated_shell only to run npm run build in the controlled VM working copy. Report the output and exit status. Do not install dependencies, modify source files, or read credentials.`，让 Agent 只在受控工作副本构建。查看真实工具记录、退出状态与构建日志，不能把口头回复当执行。通用 Shell 的源码回传不会带回 `dist`、`node_modules` 等生成目录，不能要求宿主「代码」页必定出现 VM 内的构建产物；产物回收/构建导出需通过专用后端通道，由技术侧协助确认。若使用 8A 现成项目，它只有 `dev`，没有 `build`，请把构建记未测或先按上面的新建方案准备，不能要求运行一个不存在的脚本。没有新增独立 Web 发行打包按钮，项目 ZIP 导出也不是构建成功的替代证据。

**8C Agent 自动试玩，另有模型费用**：

1. 在 Electron 桌面端选本次要验收的 Kunpo 主 Agent，确认当前项目的预览已能手动打开。
2. 预览工具栏有悬停为「Agent 试玩时显示窗口」的按钮，开启以便观察。它只控制观看已有会话，不会自己启动 Agent。
   开启后提示变为「隐藏 Agent 试玩窗口」；完整退出再启动后默认为关闭，Agent 试玩窗红叉也会关闭显示开关。工具截图可以在窗口隐藏时成功，不能据截图认定桌面上显示过窗口。观察时录制整个桌面并留意其他窗口/桌面；主预览与 Agent 是独立页面，主预览计数不必跟随 Agent。未实际看到独立窗口时，将「窗口显示」单列为未确认。
3. 使用现成 CU 项目时先发：`Use game_use to open this test game, click the counter button once, capture a screenshot, report the count actually visible, then close the playtest session. Do not modify source files, generate media, or call other external services.`（打开、点击、截图核对、关闭，不改文件。）
4. 查看工具记录中实际的 open、act/capture、close 及截图，按页面行为核对，不能只凭 Agent 口述“通过”。仅人手点 Play 成功，不算自动 game_use 成功。
5. **完整按键/触摸选测**：现成 CU 页面只有点击计数，没有 Enter/触摸独立计数；要区分这两项，使用上面新建方案中带三个计数的页面，再发 `Use game_use to press Enter once and touch the button once. Capture a screenshot, report the separate key and touch counts actually visible, then close the session. Do not modify files or generate media.`。鼠标、触摸可能共同影响按钮点击计数，以页面定义为准，不要求它描述页面上不存在的字段。

动态预览、isolated_shell 在 VM 工作副本运行，不是放开宿主 Shell。涉及依赖准备时只接受受审的公共锁文件子集，任务无直连外网；配额、网络或并发冲突拒绝属于安全边界，先记录错误，不改权限、放网或覆盖宿主新编辑。Shell 取消、并发回传冲突、后代进程回收需要专门技术验收；首次使用者可记「需协助」，不要拿真实业务文件故意制造冲突。原生引擎/外部 CLI/MCP/插件不在已恢复范围。

**查看执行卷名额，无需模型**：设置左栏→「执行卷」，查看共享的驻留配额、休眠卷和所属项目。驻留不等于正在运行；未回传修改会另行标注。页面和「刷新」都不会启动 VM。VM 已停止时，有历史快照则显示其时间及「上次记录」，没有则显示使用量未知，不能当作 8 个名额全空。完整重启应用会清空本进程的历史快照；等你正常使用需要启动 VM 后，再刷新核对。处理中或状态异常时剩余名额可显示待核验，不能凭页面数字绕过执行前的容量检查。

### 第 9 项：取消、恢复与导入导出

**删除项目与执行卷**：只用可丢弃的测试项目验收。先保存编辑，再从项目卡片菜单选择删除并阅读确认；必要时会启动已有隔离环境来核验执行卷，卡片显示等待提示并禁用重复删除。无卷、驻留卷和休眠卷均需真实核验，只有回收得到确认才删除本机项目。未回传修改、任务尚未收尾、状态损坏或结果不明时会保护项目并提示，不能靠反复点击绕过。已有“删除待完成”记录不会随应用重启自动执行，也不要手工清除；恢复修改和继续删除是分开的明确操作。详细的失败阶段及不可恢复边界见[删除与恢复](isolated-storage-lifecycle.md#deletion-and-recovery)。

**9A 重复提交防护**：观察前面的单次提交在运行中是否转成忙碌/取消状态、阻止同节点再次启动即可。真实 Key 下不要故意反复双击昂贵任务来证明防重；并发与快速双击已有模拟测试，真实计费侧仍需核账。

**9B 取消，利用已有小任务选测**：媒体节点生成中的末端 **■** 是取消，Agent 聊天运行中的停止按钮是「停止 Agent」。只在你本来就准备生成的小任务中试一次，记录点击时刻与结果；若结果已经先返回，不算测到了取消。取消后 UI 应退出忙碌或给明确错误。取消不等于上游撤单、回滚文件或退款；同步图片/音频可能没有可找回的任务，视频/3D 也可能继续在上游运行。

**9C 重开与结果未知**：先在已完成产物上检查保存、关闭、重开；这不增加生成费用。若恰逢超时、断网或退出，保留原项目/节点/型号/时间和错误，不点击「重新生成」、不换型号试运气。图片只有完整结果已保存时显示「恢复已有结果」，视频只有有效任务已保存时显示「续查已有视频」；这两个入口都不会重新提交生成，记录缺失则拒绝恢复。3D 等其他中断任务的一键续查入口仍未提供，列为技术协助项，不要求新手操作内部 API。媒体预览的「重新检查」只重取已有素材，不等于新生成；反过来，生成按钮不等于重新下载。无需为了这项专门关闭 Wi-Fi、修改代理或影响其他工作。

**9D 导出再导入，无需模型**：

1. 确认测试画布/项目已保存，回左侧「项目」列表，找到自己的测试项目卡片；点卡片右上角「…」→「导出项目」，等待下载并记下 ZIP 保存位置；若没有询问位置，查看系统下载目录。不要选择 Cloud 发布或上传社区；本地 ZIP 与那些服务无关。
2. 到「项目」页顶部悬停为「导入项目」的按钮，选择刚导出的 `.zip`；也可把**一个 ZIP 文件**拖进项目列表。不是把整个源码仓库或 `.runtime` 目录拖进去。
3. 导入会创建一个新项目，不覆盖原项目。如果列表出现同名卡片，先核对新导入项，通过它的「…」→「重命名」改成 `人工验收-导入`，保留原项目。打开新项目核对手写文字、节点参数、模型选择和已成功保存的素材；未完成任务不要在导入副本上继续点生成，以免新建收费任务。
4. 用 Finder 打开/解压这个测试 ZIP 检查文件名，确认没有 `.env`、凭据快照等秘密文件；不要把真实 Key 放进搜索框、聊天或截图来验证“没泄漏”。当前 Key 内容过滤有范围，不代表能识别所有未知秘密；有疑虑由技术侧本地脱敏检查，不上传整个 ZIP 给别人。

**失败时**：超限、损坏 ZIP、链接或受保护文件应明确报错；不要改扩展名、关闭检查、删原项目或清空运行时来重试。导入后模型仍需本机已配置凭据，项目导出不应把 Key 一起带到另一台电脑。

### 每项怎样记录，以及何时停止

每个分项记「通过 / 失败 / 未测 / 需技术协助」，不要因为某一类成功就勾全部。可直接复制这一行填写：

```text
项目名 / 分项 / 实际型号 / 规格 / 开始时间 / 点击次数 / 结果或脱敏错误 / 费用（如账号可查） / 通过、失败或未测
```

先用全新测试项目，避免业务代码/私人素材参与首次验收。真实模型产生的错误、耗时、产物质量、费用、账户配额和供应商后台行为，模拟测试都不能保证。本教程的第 3～9 项是待你手动执行的步骤，本次完善文档没有执行真实调用。

若出现 Key 明文、意外作者域名请求、越界读写、自动重发或后台任务无法停止，立即停止使用并保留脱敏证据；不要继续提交昂贵任务。报告问题优先提供点击路径、型号、时间和不含凭据的错误截图；不要发送 `.env`、凭据快照、整份私有日志或整个工作区。

## 诊断位置与证据范围

- 桌面私有日志：`.runtime/local-execution/manual-data/desktop/logs/`。
- 启动控制记录：`.runtime/local-launch/`；请不要手动编辑所有权回执。
- 应用数据与自建项目：`.runtime/local-execution/manual-data/`。
- 根 `.env` 含真实 Key 后，请只用本启动项。普通开发者 Bun 命令可能自动读取 `.env`，不属于这条受审启动链的证明范围。不要把 Key 填进提示词、项目源码或额外配置。
- 运行时和依赖不是垃圾文件；删除它们会导致启动失败。不要把整个 `.runtime`、`node_modules` 或工作区对外上传。

本轮安全检查是源码、测试与有限时间的进程/界面观测，不是全机网络抓包，也不是“绝对安全”或“没有任何 bug”的证明。公开依赖、官方开发二进制、操作系统及私有 Kunpo 服务有各自验证边界。
