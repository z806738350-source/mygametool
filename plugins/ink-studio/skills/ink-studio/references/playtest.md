# Verify in the running game

- Keep the gameplay rules and tuning explicit. In an arena survival prototype, the warning and collision logic must share the same position, geometry, and timing. Process input and simulation on one clock and draw the scene from that same state.
- Open the project with `game_use`. Inspect the page and capture the first visible arena. Start the game, send real keyboard input, and compare both world position and the character's visible movement. For survival, check that idling loses, successful dodges can lead to a win, and Restart starts cleanly. Inspect console and request failures. Close the owned test session after checking it.
- In a timed game, expose a small serializable `globalThis.__OHMYGAME_PLAYTEST__` only when the URL has `ohmygamePlaytest=1`. A `snapshot()` may report phase, player position, simulation time, warning and impact timestamps, and successful frame count. It must describe the game's actual state. If a test calls `reset()`, use the same restart path as the game.
- For a timing revision, record when the warning first appears and when the wave becomes active. Measure their simulated difference before and after the edit. Check that the warning, hit detection, and visuals still agree. Reopen a test session to load changed files.
- Try ordinary Play as well. Keep the game usable without a test bridge. If portable export is requested, start the exported files using a separate static HTTP preview, with the relative runtime imports working and without host paths.

- Verify in stages: first frame, player movement, projectile across distinct backgrounds, enemy, then individually moving Boss parts. Compare actual images with game state and collision timing. Record relevant console errors and check visible warning, loss, win and restart; finite Node data or successful WebGL setup alone cannot establish visual correctness.
- A replayed tool receipt is historical evidence, not a current window or fresh screenshot. After closing a session use a new logical `open`; verify a visible version marker or changed content and real input in that new session. Report if the tool cannot establish whether a previous input or window is still live; never repeat an uncertain action to force a result.
- Exercise ordinary Play, window reopening and closure as well as the owned Agent playtest. Normal gameplay must work without the test bridge. Check that repeated open/close does not accumulate animation loops or listeners; close the Agent session when done. Report actual device, render size and entity count with measured frame timing if making a performance claim.
