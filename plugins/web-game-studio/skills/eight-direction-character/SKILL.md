# Eight Direction Character

Work in the current Web Game project. For a full set, set `plan.delivery` on the first plan to `complete-set` or, when the user also wants to play it, `complete-set-and-playtest`. Omit it for a sample, a requested review checkpoint or a single revision. Review each direction yourself and continue within the user's request, model choices, spending limits and requested checkpoints.

1. **Find the source.** Open a chat attachment with `read_attachment` using its exact receipt. For a Canvas selection, look up the node's `data.assetId` in `canvas/assets.json` and open its saved path with `read_project_file`. Use the controlled `read` tool when offered instead. Use the game's camera and display size, or infer them from the brief and reference in a blank project. When resuming, read `assets/generated/character-sets/<setId>/authoring.json`, the current manifest and the original job receipts. Keep accepted directions.
2. **Prepare the front (S).** Inspect the original's facing, stance and transparency with [directions.md](references/directions.md). Check `list_media_capabilities` for `image`. Follow [generation.md](references/generation.md) to save a `plan` with `prepare_character_views`. Register an existing suitable transparent front. When S is missing or the user asks for a fresh S, plan only S, generate it and inspect it. Adopt the reviewed source as both the new design revision's baseline and its S view. This carries the original and brief forward.
3. **Generate one direction, then inspect it.** Start with a missing N. Use the accepted N for NW and NE, then fill the sides and front diagonals. For each missing direction, call `generate_canvas_media` with the planned board and node IDs. Send one generation per tool-call round. All eight rounds can run under the same user message. Open the receipt’s `reviewRead` with `read_project_file` or the controlled `read` tool. Its `reviewColumns` identify the candidate and available comparison views. Check the head, torso and planted feet separately. For a diagonal, compare how far each part turns from straight ahead or behind and compare it with the opposite diagonal when available. If any part still faces the straight view or the two turns disagree, revise that direction, inspect the new pixels and only then continue. If a request is interrupted, recover its original job.
4. **Align and publish.** Review the front, rear and side transitions in groups of three as described in [alignment.md](references/alignment.md). Compare all views at the same raw scale. Measure each crown and planted-foot point from the native pixels. Follow [delivery.md](references/delivery.md) to publish the PNGs and manifest, or revise one direction while preserving the other seven. For a requested game preview, load the published manifest in the existing game or a minimal viewer in a blank project. Verify switching, movement and foot contact.

Read each linked reference at its step with `read_workflow_guide`, for example `{"guide":"eight-direction-character","reference":"generation.md"}`. Ask when a missing reference, design choice or authorization affects the next action. For animation frames use the Sprite Pipeline guide.
